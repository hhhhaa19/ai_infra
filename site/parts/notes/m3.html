模块 3

C++ 必备：对象、所有权、引用与文件

解决什么问题：读懂 SDK 接口并正确管理资源。ILogger 是接口，Logger 实现日志回调；unique_ptr 管理独占所有权，其他指针和引用可以借用，但不延长生命周期。下面先走一遍最常用的部分，再按仓库代码细讲。

1从项目代码入门

SDK 接口与资源管理

写 TensorRT 程序时，最先碰到的是接口类。ILogger 是 TensorRT 定义的接口，我们写 Logger 实现它的 log 函数，TensorRT 需要打印日志时就回调它。这里用到虚函数：调用方只知道基类，实际运行子类的实现。基类的析构函数要写成 virtual，这样经基类指针释放对象时才能正确析构。explicit 用来限制隐式转换。

接着是对象归谁管。函数参数写 T 通常会复制；写 T& 是引用，可以修改原对象；写 const T& 就不能通过它修改成员。unique_ptr 独占所有权，离开作用域时自动释放；普通指针和引用只是借用，不会延长对象的生命周期。

T value;  T& ref = value;  T* ptr = &value;
unique_ptr<T> owner{factory()};  owner.get() → 普通指针；*owner → 对象

GPU 资源也要管理。cudaEvent_t 只是 CUDA 句柄，不会自动释放，所以我们自己写 CudaEvent 包一层，在构造时 create，析构时 destroy。这种做法叫 RAII：把资源的生命周期绑定到对象上。同样，DeviceBuffer 禁止拷贝，避免两个对象重复释放同一块显存。

DeviceBuffer(const DeviceBuffer&) = delete;              // 禁止拷贝，避免重复释放
~DeviceBuffer() { /* 释放显存 */ }
stream 后声明先析构：等待 GPU → 释放 buffer → context → engine → runtime

出错时也要保证资源释放。CHECK_CUDA(call) 执行一次调用，判断错误码，失败时 return 1。宏里的 return 退出的是所在函数，局部对象会正常析构。而 std::exit 不展开栈上局部对象的析构，所以不适合这里。析构函数不能返回错误码，所以里面不能用含 return 1 的宏。

解析命令行参数时也要检查。std::stoi(s, &used) 返回数值，并写出解析了多少个字符。检查 used 是否等于字符串长度，就能拒绝 256abc 这样的输入。

读取 engine 文件

engine 要先从文件读进内存。ifstream 用来读，ofstream 用来写。打开时可以加选项：binary 按字节处理，ate 打开后定位到末尾，trunc 清空原文件。读取过程是：用 ate 打开，tellg 得到文件大小，seekg 回到开头，用 vector<char> 分配内存，再 read 读入。

deserializeCudaEngine(data, size) 接收的是内容地址和长度，不是 &file：file 是流对象，它的地址不是文件内容。类型转换上，reinterpret_cast<char*> 把同一地址当字节缓冲区；static_cast 转换长度类型；1ULL 让乘法从宽类型开始，避免溢出。

kernel 中的模板

kernel 里常用模板 template<int BLOCK_THREADS>，它提供编译期整数，不是默认线程数。rmsNormCub<256><<<rows,256>>> 里两个 256 含义不同：前者决定编译出的代码，后者决定运行时启动的线程数，两者要匹配。

用 CUB 时，using Reduce = ... 只是类型别名，不创建对象，也不分配空间。typename Reduce::TempStorage 是依赖模板参数的嵌套类型，所以要写 typename；用它定义的 temp 才是对象。lambda 的 [&] 按引用捕获，同样不延长对象生命周期。

下面第 1～11 节按仓库代码把这些语法细讲一遍，第 12 节是项目里还没用到、面试常问的内容。

2编译与类型

头文件、编译单元与链接

每个 .cpp / .cu 单独编译成一个目标文件，这个范围叫编译单元。链接器再把多个目标文件和库接起来。#include 只是把文件内容原样粘贴进来。

语法含义仓库里的例子
#pragma once同一编译单元里，这个头文件只粘贴一次launch.cuh 第 1 行
声明告诉编译器"有这个东西"NvInfer.h 里的接口
定义给出实际内容。普通函数在整个程序里只能定义一次函数体、类的成员实现
函数前的 static函数只在本编译单元可见，不和其他文件重名冲突static int chooseBlock(...)
匿名 namespace { }里面的名字只在本编译单元可见plugin.cu 的 RmsNormPlugin
 
【static 的三种常见用法】
static int f();                    // 文件级函数：只在本编译单元可见
static const int sms = ...;        // 函数内：程序里只初始化一次，之后保留
class A { static int count; };     // 类成员：所有对象共用一份

【模板为什么放头文件】
launchReg<BLOCK> 不是一个现成函数，用到 launchReg<512> 时编译器才生成代码。
生成时必须看得到函数体，所以模板的定义通常写在头文件里。

【launch.cuh 的注释】
它 include 了 kernels.cu，里面有非模板 kernel。
所以同一个 .so 只能有一个 .cu 包含它，否则同一函数会被定义多次。

对应模块 2：编译产生目标文件，链接产生 .so 或可执行程序。

指针、const 与长类型

长类型从变量名开始，从右往左读。* 读作"指向……的指针"。const 修饰它左边的东西；如果左边没有东西，就修饰右边。

写法读法能改什么
float* p指向 float 的指针指针和数据都能改
const float* p指向只读 float 的指针，等同 float const* p能改指向，不能通过它改数据
float* const p只读指针，指向 float能改数据，不能改指向
void const* const* inputs指向"只读指针"的指针，那些只读指针指向只读数据输入数组和输入数据都不该改
void* const* outputs指向"只读指针"的指针，那些指针指向可写数据不能换地址，但能写输出数据
 
【enqueue 为什么是两层指针】
inputs    → [ x 的地址, weight 的地址 ]   // 一个地址数组
inputs[0] → x 的数据
void 表示"类型未知"，所以使用前要转换：
static_cast<float const*>(inputs[0])

【void* 为什么常见】
SDK 要接收任意类型的数据，所以接口写成 void*，由调用方自己知道真实类型。
代价是编译器不再帮你检查类型。

【引用和指针】
Dims const& d = inputDesc[0].dims;   // d 是别名，不拷贝，不能重新绑定
指针可以为空、可以改指向；引用一定绑定一个对象，绑定后不能换。

3对象与所有权

类、继承与 plugin 接口

plugin.cu 是 C++ 面向对象语法最集中的文件。TensorRT 只认识基类接口，手里拿的是基类指针；调用时通过虚函数跳到 RmsNormPlugin 的实现。这就是动态分派。

class RmsNormPlugin : public IPluginV2DynamicExt { ... };

int32_t getNbOutputs() const noexcept override { return 1; }
│                       │     │        └─ 检查：必须真的重写基类虚函数，写错签名就报错
│                       │     └─ 承诺不抛异常
│                       └─ 这个成员函数不修改对象
└─ 固定 32 位整数

Logger final : public ILogger         // final：不允许再继承
virtual void f() = 0;                 // 纯虚函数：基类只规定接口，子类必须实现

【虚函数的常见实现】
每个有虚函数的类有一张函数地址表（vtable），对象里存一个指向它的指针。
调用虚函数时：读对象里的指针 → 查表 → 跳转。C++ 标准没有规定必须这样实现，但主流编译器都这样做。

【构造函数】
explicit RmsNormPlugin(float eps) : eps_(eps) {}
// : eps_(eps) 是初始化列表：成员在进入函数体之前就初始化
// explicit：不允许 float 隐式变成 RmsNormPlugin

RmsNormPlugin(void const* data, size_t) { ... }
// 同名不同参数，叫重载。这里对应 plugin 的两种创建方式
// size_t 没写参数名：表示这个参数不用

【成员的默认值和命名】
float eps_ = 1e-6f;                   // 构造函数没设时才用这个默认值
std::string ns_;                      // 后缀 _ 是成员变量的命名习惯，不是语法

【为什么 private 里要写 using】
using IPluginV2::getOutputDimensions;
子类只要定义了同名函数，基类的同名重载就会被隐藏，编译器会发出警告。
这里把基类名字引入进来，消除"同名函数被隐藏"的警告。

【delete this】
void destroy() noexcept override { delete this; }
对象在 plugin 的 .so 里 new，所以也由同一个 .so 里的代码 delete。
delete this 之后不能再访问任何成员。

【生命周期规则】
局部对象按声明的逆序析构。所以被依赖的对象要先声明：
Logger logger;                        // 最先声明，最后析构
unique_ptr<IBuilder> builder{...};    // 用到 logger
这就是 build_engine.cpp 里"Logger must outlive"注释的意思。

【悬空指针】
const char* bad() { std::string s = "x"; return s.c_str(); }   // 错：s 已析构
const char* ok()  { return "x"; }                              // 对：字面量活到程序结束
launchRMSNorm 返回错误字符串是安全的，因为返回的都是字面量。

【为什么 creator 的 fields_ / fc_ 要做成员】
fc_.fields = fields_.data();
getFieldNames() 返回 &fc_，TensorRT 之后还会读这个地址。
如果写成局部变量，函数返回后这些内存已经失效，指针就悬空了。

【vector 扩容】
vector 空间不够时会换一块内存，之前的 data() 指针全部失效。
所以构造函数先 emplace_back，再取 fields_.data()。顺序不能反。

【值复制 vs 引用】
const auto shape = input->getDimensions();  // 得到一份副本
Dims const& d = inputDesc[0].dims;           // 只是别名，没有复制

拷贝、移动与 RAII

持有资源的类默认被拷贝时，只会拷贝指针值，两个对象就指向同一块资源，最后释放两次。所以 DeviceBuffer 删除了拷贝。

struct DeviceBuffer {
    void* ptr = nullptr;
    DeviceBuffer() = default;                            // 用编译器生成的默认构造
    DeviceBuffer(const DeviceBuffer&) = delete;          // 禁止拷贝构造
    DeviceBuffer& operator=(const DeviceBuffer&) = delete; // 禁止拷贝赋值
    ~DeviceBuffer() { if (ptr) cudaFree(ptr); }
};

DeviceBuffer a;
DeviceBuffer b = a;       // 拷贝构造：用 a 创建新对象（已禁止）
b = a;                    // 拷贝赋值：两个对象都已存在（已禁止）

【移动的作用：把所有权转走】
用户声明了拷贝构造后，编译器不再自动生成移动构造，所以 DeviceBuffer 现在也不能移动。
如果要放进 vector 或从函数返回，需要自己写移动：

DeviceBuffer(DeviceBuffer&& o) noexcept : ptr(o.ptr) { o.ptr = nullptr; }

把旧对象的 ptr 清空，它析构时就不会重复释放。

【五法则】
析构、拷贝构造、拷贝赋值、移动构造、移动赋值里，自定义了一个，就要考虑其余四个。
只有一块资源时，优先直接用 unique_ptr 管理，这样往往都不用手写。

struct 和 class 只有一个语法区别：struct 默认 public，class 默认 private。

4模板、lambda 与宏

模板与编译期常量

这是 RMSNorm 项目最核心的 C++ 技巧。kernel 的线程数是模板参数，编译时就要确定，这样编译器才能做特化优化；但 b 是运行时算出来的，不能直接写成 launchReg<b>。

【问题】
const int b = chooseBlock(n, rows);    // 运行时才知道
launchReg<b>(...);                     // 编译错误：模板参数必须是编译期常量

【解法】每个可能的值都写一个 case，让 switch 在运行时选
template <class F>
static bool withBlock(int b, F f) {
    switch (b) {
        case 128:  return f(std::integral_constant<int, 128>{});
        case 256:  return f(std::integral_constant<int, 256>{});
        ...
    }
    return false;
}

【调用】
withBlock(b, [&](auto blk) {
    return launchReg<decltype(blk)::value>(rows, n, x, w, y, eps, s);
});

【一步步看】
integral_constant<int, 128>   一个类型，它的静态成员 value 等于 128
[&](auto blk) { ... }         泛型 lambda：blk 的类型由实参决定
decltype(blk)                 取 blk 的类型
decltype(blk)::value          从类型里取出 128，这是编译期常量

每个 case 传入的类型不同，lambda 就生成一个不同版本，
所以 launchReg<128>、launchReg<256> 都被实例化出来了。
好处：四个 launchXxx 共用一个 switch，不用各写一遍。

【代价】
每个实例都是一份单独的机器码，所以要控制组合数量。
launchReg 的 P 只列了 1、2、4、8、9、16、17、32、33，而不是全部整数。
【其他模板语法】
template <int BLOCK>          // 非类型模板参数：一个编译期整数
template <class F>            // 类型模板参数：一个类型，这里是 lambda 的类型
typename Reduce::TempStorage  // 告诉编译器这个依赖模板的名字是类型
constexpr char const* kName   // 编译期常量
decltype(x)                   // 取表达式的类型，不计算它
auto* p = new T(...);         // 自动推导类型，p 是 T*

lambda

[捕获](参数) { 函数体 }

[]      不捕获
[&]     所有用到的外部变量按引用捕获
[=]     所有用到的外部变量按值拷贝
[x, &y] x 按值，y 按引用

【立即调用：chooseBlock 里的写法】
static const int sms = [] {            // 定义一个 lambda
    int dev = 0, count = 0;
    cudaGetDevice(&dev);
    cudaDeviceGetAttribute(&count, cudaDevAttrMultiProcessorCount, dev);
    return count;
}();                                   // 最后的 () 表示马上调用

组合效果：复杂初始化只跑一次，结果存进 sms，之后每次调用不再查询。
注释里写着"只看第一次用到的 GPU"，这是它的局限：多 GPU 时不会重新查询。

【捕获引用的风险】
lambda 活得比被捕获的变量更久，就会悬空，比如存起来稍后再调用。
withBlock 里是当场调用，所以 [&] 安全。

宏

宏由预处理器在编译前做文本替换，不懂类型和作用域。能用函数或模板就不用宏，但下面两种情况宏更方便。

【CHECK_CUDA：需要 return 和当前行号】
#define CHECK_CUDA(call)\
    do {\
        cudaError_t err = call;\
        if (err != cudaSuccess){\
            std::cerr << __FILE__ << ":" << __LINE__ ...\
            return 1;\
        }\
    }while (0)

反斜杠 \        把多行接成一行宏
__FILE__        当前文件名
__LINE__        当前行号，所以报错能定位到调用处
err = call      把结果存起来，保证 call 只执行一次
do { } while(0) 让宏像一条普通语句，if (a) CHECK_CUDA(x); else ... 也不会出错
return 1        是宏的关键：普通函数没法让调用者 return

【REG_CASE：生成重复代码】
#define REG_CASE(P) if (need <= P) {rmsNormReg<BLOCK,P><<<rows,BLOCK,shm,stream>>>(x,w,y,n,eps);return true;}
    REG_CASE(1) REG_CASE(2) REG_CASE(4) ...
#undef REG_CASE                        // 用完取消定义，避免影响后面的代码

【宏的经典坑】
#define SQ(x) x * x
SQ(1 + 2)   → 1 + 2 * 1 + 2 = 5，不是 9
参数要加括号，整个宏也要加括号。

5底层细节与错误处理

类型转换、大小与对齐

转换用途仓库里的例子
static_cast有明确关系的转换：数值类型、void* 转回原类型static_cast<float const*>(inputs[0])
reinterpret_cast按另一种类型重新解读同一段位，风险最大reinterpret_cast<std::uintptr_t>(p)
const_cast去掉 const，修改原本就是 const 的对象是未定义行为仓库里没用
dynamic_cast运行时检查的向下转型，需要虚函数仓库里没用
 
【固定宽度类型】
int32_t       正好 32 位
size_t        表示大小的无符号类型，64 位系统上是 64 位，sizeof 的结果就是它
uintptr_t     能装下指针的无符号整数，用来做地址运算

【对齐】
static bool aligned16(const void* p) {
    return reinterpret_cast<std::uintptr_t>(p) % 16 == 0;
}
地址能被 16 整除才算 16 字节对齐，float4 版 kernel 需要这一点。

【为什么 eps 用 memcpy，不直接强转】
std::memcpy(&eps_, data, sizeof(float));
engine 里的这 4 个字节不一定落在 4 字节对齐的地址上。
*(float const*)data 可能违反对齐和类型规则；memcpy 按字节拷，始终合法。

【位运算：把多个开关放进一个整数】
std::ios::binary | std::ios::ate        // 打开文件时同时设置两个选项
1U << static_cast<uint32_t>(nvinfer1::NetworkDefinitionCreationFlag::kEXPLICIT_BATCH)
1U << k 把第 k 位设成 1；多个开关用 | 合并，用 & 检查。

【整数溢出】
int bytes = rows * n * 4;               // 可能超过 int 范围
1ULL << 30                              // 从 unsigned long long 开始算

【enum class】
enum class 的值不会隐式转成 int，所以要显式转换：
static_cast<int>(nvinfer1::ILogger::Severity::kWARNING)
Severity 的数值越小越严重，所以 severity <= kWARNING 表示"警告及更严重"。

错误处理：为什么不用异常

C++ 能用异常，但我们的代码跨越 CUDA、TensorRT 和 .so 边界，主要靠返回值报告错误。TensorRT 接口都带 noexcept：如果异常从这种函数里跑出来，程序直接调用 std::terminate 结束。

方式含义例子
错误码返回 0 表示成功，或返回枚举cudaError_t、enqueue 返回 0 / 1
空指针创建失败返回 nullptrif (!builder)
bool只区分成败withBlock、parseFromFile
错误字符串nullptr 表示成功，否则是错误信息launchRMSNorm
 
【launchRMSNorm 为什么不用异常或 TORCH_CHECK】
launch.cuh 不能依赖 PyTorch，而且 plugin 的 enqueue 是 noexcept。
所以它返回 const char*，由调用方转换：
  plugin：打印后 return 1
  PyTorch 扩展：转换成 TORCH_CHECK 报错

【kernel 启动错误】
launch 是异步提交，<<<>>> 本身没有返回值，要另外查：
cudaPeekAtLastError()   // 看错误，不清除
cudaGetLastError()      // 取错误，并清除

【文件流的错误】
流对象可以直接判断：if (!file) { ... }
file.close() 之后再检查一次 if (!file)，才知道写入是否完整。

逐行读 RmsNormPluginCreator

class RmsNormPluginCreator : public IPluginCreator {     // 继承 TensorRT 的工厂接口
public:
    RmsNormPluginCreator() {
        fields_.emplace_back("eps", nullptr, PluginFieldType::kFLOAT32, 1);
        // 直接在 vector 内部构造一个 PluginField，描述"有个 float 属性叫 eps"
        fc_.nbFields = static_cast<int32_t>(fields_.size()); // size_t 转 int32_t
        fc_.fields = fields_.data();                         // 指向 vector 内部数组
    }

    IPluginV2* createPlugin(char const*, PluginFieldCollection const* fc) noexcept override {
        float eps = 1e-6f;                                   // 默认值，f 表示 float 字面量
        for (int i = 0; i < fc->nbFields; ++i)
            if (std::strcmp(fc->fields[i].name, "eps") == 0  // C 字符串比较内容，== 比较的是地址
                && fc->fields[i].type == PluginFieldType::kFLOAT32)
                eps = *static_cast<float const*>(fc->fields[i].data); // void* → float* → 取值
        auto* p = new RmsNormPlugin(eps);                    // 堆上创建，之后由 destroy 释放
        p->setPluginNamespace(ns_.c_str());                  // std::string 转 const char*
        return p;                                            // 子类指针隐式转成基类指针
    }
private:
    std::vector<PluginField> fields_;
    PluginFieldCollection fc_{};                             // {} 把成员初始化为零
    std::string ns_;
};

REGISTER_TENSORRT_PLUGIN(RmsNormPluginCreator);
// 展开后定义一个全局对象。全局对象在 main 之前构造，.so 被加载时也会构造，
// 它的构造函数把 creator 登记到注册表。这是 C++ 静态初始化的常见用法，
// TORCH_LIBRARY 用的是同样的思路。

项目外的高频考点

以下是通用 C++ 知识，仓库里基本没有对应代码，用来准备八股，不代表已经实践过。

【智能指针】
unique_ptr  独占，不能拷贝，只能移动，几乎没有额外开销
shared_ptr  共享，引用计数归零才释放；计数是原子操作，有额外开销
weak_ptr    不增加计数，用 lock() 取 shared_ptr；用来打破循环引用
make_unique / make_shared  优先用它们创建

【左值、右值和 move】
左值：有名字、能取地址的对象，比如 x
右值：临时值，比如 a + b
T&&：右值引用，表示"这个对象可以被搬走"
std::move(x) 本身不移动任何东西，只是把 x 转成右值，真正移动的是移动构造函数。
被移动后的对象处于有效但内容未指定的状态，不要再依赖它的值。

【vector】
size 是元素个数，capacity 是已分配容量；扩容时重新分配并搬动元素，均摊 O(1)。
reserve 提前分配，能避免多次扩容。
push_back 传入已有对象，emplace_back 直接用参数原地构造。

【const 成员函数】
void f() const：不修改成员，const 对象只能调用它。

【malloc 和 new】
malloc 只分配字节，不调用构造函数；new 分配并构造。
free 不析构；delete 先析构再释放。不能混用。

【基类析构为什么要 virtual】
通过基类指针 delete 子类对象时，析构不是 virtual 属于未定义行为，子类资源可能不释放。

【构造函数里调用虚函数】
构造基类时子类部分还不存在，所以不会分派到子类版本。

【并发】
std::thread           创建线程，结束前要 join 或 detach
std::mutex + lock_guard  互斥，RAII 自动解锁
std::atomic           单个变量的无锁原子操作
volatile              不是线程同步工具
数据竞争：多个线程同时访问同一变量且至少一个写，又没有同步，属于未定义行为。

【struct 大小和内存对齐】
struct S { char a; int b; };   // 通常 sizeof(S) == 8，a 后面补 3 字节
成员按对齐要求排列，把大成员放前面可以减少填充。

【未定义行为（UB）】
越界访问、使用已释放内存、空指针解引用、有符号整数溢出。
程序可能看起来正常，换编译选项后才出错。
