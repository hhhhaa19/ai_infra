模块 4

模型导出与正确性：张量、ONNX、误差

这一模块讲什么：模型换一个后端运行时，怎么保证算的还是同一件事。流程是：固定权重和输入 → 正确设置 PyTorch 模式 → 导出 ONNX → 用同一份输入比较输出。正确性通过以后，性能结论才有意义；但两者是两件事。

第一步：搞清楚文件里存了什么

比较之前，先分清几种文件。state_dict 保存参数和缓冲区的名字、形状和数值，不保存 forward 的执行关系，所以权重 .pt 不能单独代表模型。ONNX 同时保存计算图和权重。engine 则是针对目标环境优化后的执行方案。

input.bin 是裸字节，文件里没有写 dtype 和布局，这些要靠双方约定。我们的约定是：输入 NCHW、[1,3,224,224]、FP32，共 602112 字节；输出 [1,1000]、FP32，共 4000 字节。

张量在内存里是连续的，所以多维下标可以算成偏移：

连续 NCHW 偏移：((n*C+c)*H+h)*W+w

例：[0,1,10,20]
元素偏移 = ((0*3+1)*224+10)*224+20 = 52436
字节偏移 = 52436 * 4 = 209744

第二步：设置模型的运行方式

运行前要让模型和输入都在同一设备上：.to(device) 搬的是参数和缓冲区，输入要另外搬。调用 model(x) 才是真正的前向计算。

接着设置两个开关。model.eval() 把模块的 training 标记改为 False，Dropout 和 BatchNorm 这类层会据此改变计算：Dropout 不再随机置 0，BatchNorm 用训练时存下的统计量。所以它会影响输出。卷积、线性层不检查这个标记。

no_grad() 和 inference_mode() 不改变输出，只让 PyTorch 不为反向传播做记录。inference_mode() 比 no_grad() 省得更多，还省去版本计数和 view 记录，但它产生的张量不能再进入要求导的计算。它们控制的都是求导记录，不控制 CUDA 同步。

model.eval()                  # 让模型按推理的方式计算
with torch.inference_mode():  # 不为反向传播做记录
    y = model(x)

no_grad 的结果可以当常量继续参与训练；
inference_mode 的结果进入要求导的计算会报错。

导出 ONNX 不需要 autograd 图，因为 ONNX 只记录前向计算，权重作为常量保存。但 eval() 必须先调用，否则训练模式的计算可能被记录进去。

第三步：导出 ONNX

仓库里有两种导出。src/tensorrt_intro/export_resnet.py 用 dynamo=True：通过 torch.export 得到 aten 层的 FX 图，再按转换表翻译成 ONNX。src/llama/export_onnx.py 在 Orin 的 torch 2.1 上用老导出器：TorchScript tracing 真的跑一遍模型，得到含 aten:: 节点的 TorchScript 图，再用 symbolic 函数翻译成 ONNX。所以两边都经过 aten 算子，区别在于抓图和翻译的方式。

Quest：Python 模型 → torch.export → aten FX 图 → 翻译 → ONNX（opset 18）
Orin： Python 模型 → tracing 真跑 → TorchScript 图 → symbolic → ONNX（opset 17）

dynamo=True 是导出器选择，不等于动态形状
output_names=['logits'] 只是名字
opset_version 是算子规范版本，不是数值精度
checker / Netron 只查结构，不证明数值正确

这里容易把两件事混起来：两条路的中间图看起来都有 aten，但 Quest 那条是 FX 图，Orin 那条是 TorchScript 图。另外，名字叫 dynamo=True，新版 torch.export 不一定走 Dynamo 的字节码抓图，取决于 torch 版本和导出策略，这点没在 Quest 上确认。如果 RmsNorm 改走 Quest 这条路，register_custom_op_symbolic 就不能用了，要改用转换表（custom_translation_table），Meta 实现可以用来推形状。这条路还没实际跑过。

第四步：验证数值

比较时要用同一份 input.bin，把 output_ref.bin 和 output_trt.bin 放在一起看。先查基础项：字节数、shape、dtype、有没有 NaN / Inf。基础项没问题，再逐项比较所有 logits。比的是 logits，不能和 softmax 概率混在一起比。

abs(actual - reference) <= 1e-5 + 1e-4 * abs(reference)
当前：1000 个输出 PASS，Top-1 258 / 258

为什么不能只看 Top-1？Top-1 只比较最大值的位置。比如 logits 整体放大 10 倍，Top-1 不变，但概率已经错了。所以 Top-1 一致只能算最基本的检查。

反过来，如果已经知道每个元素的绝对误差不超过 ε，而且前两名差距大于 2ε，就能证明 Top-1 不会变。设第一名是 a，第二名是 b，其他任一类是 c（c ≤ b）。部署后 a′ ≥ a − ε，c′ ≤ c + ε ≤ b + ε，所以 a′ − c′ ≥ (a − b) − 2ε > 0，第一名仍然最大。

换精度时要注意什么

后面的 FP16 路线会改变数值。FP32 精度最高；FP16 范围较小，但尾数比 BF16 细；BF16 范围接近 FP32。.half() 可能发生舍入、溢出、下溢，再转回 FP32 也恢复不了丢失的信息。autocast 按规则为算子选择精度；GradScaler 只用于训练。

大模型加载时占多少内存

大模型要分开看三块：CPU 加载时的峰值、GPU 上权重的容量、运行时的 activation / KV / workspace。分片和 meta 初始化能降低加载峰值，但不会让最终权重变小；真正压缩权重要靠量化。

面试要求

必须会

  • 导出前为什么要 model.eval()（Dropout、BatchNorm 行为不同）；no_grad / inference_mode 只是省反向记录。
  • ONNX 导出的两种路径（TorchScript 老导出器、dynamo=True），opset 是什么、为什么 opset 会影响 TensorRT 能不能解析（ACT 的 opset 17 LayerNormalization，TensorRT 8.5 不认识，改用 opset 16）。
  • 误差指标各回答什么：最大绝对误差、相对 L2、余弦相似度、逐元素相对误差（分母接近 0 时会被放大，不能单看）。
  • "多少算大"的三层判断：数值层（和 FP32 比）→ 任务层（Top-1、动作误差）→ 系统层（闭环成功率）。

应该会

  • 换精度时要注意什么：FP16 的范围和精度、溢出、累加用什么精度；BatchNorm 折进卷积。
  • 把预处理 / 后处理（归一化、反归一化）放进 ONNX 的好处和代价（ACT 就这么做的）。
  • 加载大模型时的内存占用估算（参数量 × 字节数，加上中间激活）。

加分

  • 自定义算子怎么导出（symbolic、custom_translation_table）。
  • ONNX 图清理：常量折叠、去掉冗余的 Squeeze / Unsqueeze（ACT 2945 个节点里有 1212 个）。
