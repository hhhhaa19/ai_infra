# 核心算子：Softmax，从三遍读到 online softmax

**主线**：softmax 把一行分数变成概率（lm_head 后的采样、attention 的权重），计算很少，是带宽问题；每行要先做两次规约（最大值、求和）。优化沿两个方向：**分工**（一行交给 1 个线程 / 1 个 block / 1 个 warp）和**算法**（读 3 遍 / 2 遍 / 1 遍）。最后按行长 n 分档派发。online softmax 是 FlashAttention 的核心。

## 结果总览

Orin，锁频，FP32；GB/s 按读 X 一遍 + 写 Y 一遍计算，括号是占 copy 的比例。全部和 CPU double 比，误差 < 1e-6。

| rows × n | ① naive | ② block | ③ online | ④ warp |
|---|---|---|---|---|
| 65536 × 128 | 13.3（8%） | 34.1（19%） | 35.4（20%） | 190.2（108%） |
| 16384 × 1024 | 11.3（6%） | 167.8（94%） | 165.5（92%） | 189.4（106%） |
| 4096 × 4096 | 19.8（11%） | 189.9（106%） | 179.1（100%） | n > 1024 不适用 |
| 512 × 32000 | 6.3（4%） | 87.2（49%） | 113.4（63%） | 不适用 |

- 前三组模拟 attention（一行 = 一个 token 对所有 token 的分数），最后一组模拟 512 个请求对 32000 词表采样。
- 超过 100% 是因为 copy 本身只到约 178 GB/s；190 约是 DRAM 上限 204.8 的 93%。
- 下面的原因按读写份数和缓存大小估算，没有用 ncu 验证。

| 版本 | 分工 | 读 X 几遍 | 每元素 exp | 同步 | 适合 |
|---|---|---|---|---|---|
| ① naive | 1 线程 1 行 | 3 | 2 | 无 | 都不适合 |
| ② block | 1 block 1 行 | 3（后两遍可能命中缓存） | 2 | 16 次 | 中等 n（1024～4096） |
| ③ online | 1 block 1 行 | 2 | 3 | 有 | 很长的 n（32000） |
| ④ warp | 1 warp 1 行 | 1 | 1 | 无（shuffle） | n ≤ 1024 |

## 公式、减最大值、两个坑

```text
y_j = e^(x_j − m) / Σᵢ e^(xᵢ − m)，m = 这一行的最大值
x = [102, 101, 100] → 减 102 → [0, −1, −2] → y = [0.665, 0.245, 0.090]，和 [2, 1, 0] 一样
```

- **为什么减最大值**：e^x 在 x > 88.7 时溢出成 inf。减完最大的是 0，其余 ≤ 0，分母至少是 1；分子分母同乘 e^(−m)，结果不变。
- **每行各算各的**：不同行完全独立，随便分给线程；一行内部要规约，需要线程合作。
- **坑 1**：最大值从 `-INFINITY` 开始，不能从 0（全负的行会得到 0 / 0）。
- **坑 2**：分不到数的线程，求最大值填 −∞、求和填 0。
- `expf` 精确；`__expf` 走 SFU（`MUFU.EX2`）更快，减完最大值后输入在误差小的区间；`exp2f` 用于已乘好 log₂e 时。softmax 卡在带宽，换快速版收益不确定（没测）。

## ① naive：一个线程一行（copy 的 4～11%）

```text
int r = blockIdx.x * blockDim.x + threadIdx.x;   // 全局行号
if (r >= rows) return;
size_t base = size_t(r) * n;
float m = -INFINITY;  for (i…) m = fmaxf(m, X[base+i]);          // 第 1 遍
float d = 0.f;        for (i…) d += expf(X[base+i] - m);         // 第 2 遍
                      for (i…) Y[base+i] = expf(X[base+i] - m) / d;   // 第 3 遍
```

- **为什么慢**：一个 warp 的 32 个线程同一时刻读 32 个不同的行，地址相隔 n 个 float，每个数占一箱。
- 512 × 32000 最慢（4%）：只有 512 个线程在干活。

## ② block：一个 block 一行

```text
template <int BLOCK>   // launch: softmax_block<256><<<rows, 256>>>
int b = blockIdx.x, r = threadIdx.x;  size_t base = size_t(b) * n;
__shared__ float mb[BLOCK], sumb[BLOCK];
float m = -INFINITY;
for (int i = r; i < n; i += BLOCK) m = fmaxf(m, X[base + i]);   // 相邻线程读相邻元素
mb[r] = m;  __syncthreads();
for (int off = BLOCK/2; off > 0; off /= 2) {
    if (r < off) mb[r] = fmaxf(mb[r], mb[r + off]);
    __syncthreads();                       // 放在 if 外面
}
float row_max = mb[0];                      // 所有线程都拿到结果
// 同样再规约一次求 row_sum，最后 Y[base+i] = expf(X[base+i] - row_max) / row_sum
```

- **n = 1024、4096 接近 copy**：一行 4～16 KB，第 1 遍读完还在 L1 / L2，后两遍几乎不回 DRAM。
- **n = 32000 只有 49%**：一行 125 KB 放不进缓存，读 3 写 1 = 4 份数据，copy 是 2 份，约 50%。→ ③ 解决。
- **n = 128 只有 19%**：256 个线程一半闲着，两次规约 16 次同步只处理 128 个数。→ ④ 解决。

## ③ online softmax：最大值和分母一遍求出（n = 32000：49% → 63%）

```text
读到新数 x：  m_new = max(m, x)
              d     = d × e^(m − m_new) + e^(x − m_new)
              m     = m_new
两组合并：    m = max(m₁, m₂)
              d = d₁ × e^(m₁ − m) + d₂ × e^(m₂ − m)
```

- **思路**：先用"目前的最大值"算分母，遇到更大的数时把之前的 d 整体乘 e^(m − m_new) 修正。
- **并行**：每个线程各算一组 (m, d)，规约时用合并公式代替加法。总共读 2 遍：一遍求 (m, d)，一遍写 y。
- **结果**：n = 32000 读 2 写 1 = 3 份，约 copy 的 2/3，实测 63%；n = 1024、4096 本来就命中缓存，反而略慢（每个数多算一次 exp）。
- **更大的意义**：(m, d) 能随时合并，一行就能拆给多个 block 各算一段再合并（Flash-Decoding：decode 时行少、KV cache 很长）；FlashAttention 一块一块地算，不用存整行分数。

**动画 · online softmax 逐个读入**：看 m 变大时 d 怎么被修正，最后和三遍算法对照。

> 易错：两个空线程合并会得到 NaN
>
> 。n 小于线程数时有线程是 (−∞, 0)，两个空线程合并时 −∞ − (−∞) = NaN，一路传上去整行都是 NaN。合并前判断 m_new 是 −∞ 就跳过；只有一边空没问题（e^(−∞) = 0）。

## ④ warp 版：一个 warp 一行，整行放进寄存器（n = 128：20% → 108%）

```text
template <int PER_LANE>   // = ceil(n / 32)；n ≤ 1024 → PER_LANE 1/2/4/8/16/32
int lane = threadIdx.x % 32, warp = threadIdx.x / 32;
int row  = blockIdx.x * (blockDim.x / 32) + warp;    // 一个 block 4 个 warp = 4 行
if (row >= rows) return;                              // 整个 warp 一起退出，shuffle 仍安全
float v[PER_LANE];
#pragma unroll
for (int k = 0; k < PER_LANE; ++k) {
    int i = lane + k * 32;                            // 交错分配：固定 k 时 32 个线程读连续 128 字节
    v[k] = (i < n) ? X[base + i] : -INFINITY;
}
float m = warp_max(max of v[k]);                      // __shfl_xor_sync，5 步
float d = 0.f;  for (k…) { v[k] = expf(v[k] - m); d += v[k]; }   // exp 结果存回 v[k]
d = warp_sum(d);  float inv = 1.f / d;
for (k…) if (lane + k*32 < n) Y[base + lane + k*32] = v[k] * inv;
```

- **为什么快**：只读 X 一遍；不用 shared、不用 `__syncthreads()`，规约只有 10 次 shuffle。
- **PER_LANE 必须是模板参数**：`v[]` 的大小和下标在编译时确定，循环才能展开、`v[k]` 才在寄存器里；否则掉进 local memory。`-Xptxas -v`：PER_LANE = 32 用 48 个寄存器、0 spill。
- **不用 online**：数据已经在寄存器里，再遍历不花显存带宽；两遍算法每个元素只算 1 次 exp，online 要 2 次。**放不进寄存器用 online，放得进用两遍。**
- **一个 block 放 4 个 warp**：每 SM 最多 16 个 block，1 个 warp 一个 block 时占用率最多 16 / 48 = 33%。

**动画 · warp 内规约：xor vs down**（8 个 lane 演示）：

- `__shfl_xor_sync(mask, var, laneMask)`：异或的是 **lane 号**，两两互换，所有 lane 都拿到结果（butterfly）。
- `__shfl_down_sync`：单向往下传，只有 lane 0 对，还要再广播一次。softmax 每个 lane 都要用 max 和 sum，所以用 xor。
- mask 里的 lane 必须都执行到 shuffle，所以前面不能有部分线程 return。

## 按 n 分档

- **n ≤ 1024**：warp 版（整行进寄存器，读 1 遍）。
- **中等 n**（几千）：block 版（后两遍命中缓存）。
- **很长 n**（词表 32000）：online 版（读 2 遍）；行很少时再把一行拆给多个 block（Flash-Decoding，没做）。

和 RMSNorm 按 n 分档、n ≤ 256 一个 warp 一行是同一个思路，cuDNN、PyTorch 也这样按形状派发。

## reduction 写对的前提

| 写法 | 隐含前提 | 不满足时 |
|---|---|---|
| stride 从 blockDim/2 减半 | blockDim 是 2 的幂 | 有元素被漏掉 |
| 读输入不判断边界 | n 等于线程总数 | 越界读 |
| 直接写 `out[0]` | 只有 1 个 block | 多个 block 互相覆盖（要 atomicAdd 或第二个 kernel） |
| `__shfl_down_sync(0xffffffff, …)` | blockDim 是 32 的倍数 | 最后一个 warp 不满时结果未定义 |
| 测试用 `!=` 精确比较 | 输入是小整数 | 浮点加法顺序不同就有微小误差 |

更快的写法：warp 之间合并时，各 warp 的部分和写进 shared，再让 warp 0 读进来做一次 shuffle，只要 1 次同步。

## 面试要求

softmax（含 online softmax）是手写 CUDA 题里的高频题，也是理解 FlashAttention 的前提。

### 必须会

- 公式；为什么要减最大值、为什么结果不变、为什么减完就安全（88.7 的溢出边界）。
- 当场手写 block 版：两次规约、结果广播给所有线程、循环从 `i = r` 开始、规约条件 `r < offset`、`__syncthreads()` 放在 if 外面；最大值初值 −INFINITY、越界填 −∞ / 0。
- online softmax 的更新公式和两组合并公式，能用 [2, 1, 3] 手算一遍；为什么只读两遍。
- 为什么 naive 慢（warp 内地址不连续）。

### 应该会

- 用数字讲：512 × 32000 上 block 49% → online 63%，按读写份数（4 份 → 3 份）解释；n = 1024、4096 为什么三遍也接近 copy（缓存）；n = 128 为什么换算法没用。
- 空线程合并 −∞ − (−∞) = NaN 的坑和改法。
- 分工和算法两个方向；warp 版为什么适合短行（只读一遍、xor shuffle、不用同步），n = 128 上 20% → 108% 的数字；为什么 warp 版用两遍算法而不是 online（数据在寄存器里，少算一半 exp）。
- 按 n 分档：n ≤ 1024 warp、中等 block、很长 online；PER_LANE 模板参数和寄存器上限。
- `expf` / `__expf` / `exp2f` 的区别。
- reduction 的几个隐含前提（2 的幂、32 的倍数、单 block、精确比较）。

### 加分

- FlashAttention 怎么用 online softmax 分块、不存整行分数；Flash-Decoding 把一行拆给多个 block。
- 和前后算子融合（scale、mask、softmax 合成一个 kernel）。

三档的含义见复习笔记顶部说明。
